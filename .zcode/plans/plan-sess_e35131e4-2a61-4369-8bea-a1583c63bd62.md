# 收尾 `--dual-scaf`：提交在途批次 + 移植 `trans_base_infer`

## Context（背景）

rshifiasm 是 hifiasm `0.25.0-r726` 的 Rust 移植（目标逐字节一致输出）。HiFi 默认链路 P0–P6 与整个 trio 家族已完成，但工作树里压着 **~13.7k 行未提交工作**（15 个文件修改 +3,145 行、8 个新模块 10,520 行）：`--trio-dual`、`-5` 多倍体、`--dual-scaf` 三个特性，前两个已完成过门禁，`--dual-scaf` 在当前语料输出已逐字节一致。

`--dual-scaf` 的唯一缺口是 `trans_base_infer`（[inter.cpp:22574](/home/keith/projects/hifiasm/inter.cpp)，RC_3 基础级过渡）：索引半（[trans_base.rs](/home/keith/projects/rshifiasm/src/assembly/trans_base.rs)）和种子/链化半（[qgen_input.rs](/home/keith/projects/rshifiasm/src/overlap/qgen_input.rs)）已写好但**没有 driver 接线**——`dual_scaf.rs:342` 把建好的索引 `let _index` 丢弃，qgen_input 两个入口零调用者。后果：C++ 参考的深过渡表比 Rust 多一条 `RC_2`（qn=2→tn=6，来自 `clean_u_trans_t_idx_adv` 的 RC_3→RC_2 降级）且同批过渡 `nw`/端点不同；当前语料上这些过渡全被链接阶段过滤所以输出仍一致，但数值层不等价。`gen_bp_phasing` 路径（Overlaps.cpp:17572）已被 C++ 注释掉，trio-dual 不受影响；另两个活跃调用点属 Hi-C（P7），本次移植为其铺路。

## 风险

- `push_wlst_exz`/`ovlp_base_direct`/`rechain_aln` 的 UL 语义（`is_ualn_win` 未对齐窗口标志）是 P4 窗口机制没有的扩展，需给 Rust 窗口模型补标志位——这是最容易出错的一块
- B 部分合计约 1.5–2k 行新 Rust，量级与已完成的 ctg_trans.rs/scaf_tangle.rs 相当
- `.ec.bin` padding 等既有豁免项保持不变
